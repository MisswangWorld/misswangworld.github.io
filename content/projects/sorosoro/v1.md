# SoroSoro

**SoroSoro** (そろそろ) is a Japanese word meaning "about time" — that quiet, creeping awareness that you really should get around to something. Not an urgent alarm, just a gentle nudge: *it's time*.

That feeling is exactly what this app is built around: no pressure, no anxiety, just a clear view of the promises you've made to yourself.

---

## What It Is

SoroSoro is a **commitment tracker** — not a calendar, not a reminder app, not another to-do list.

It asks one question: *Did you follow through on what you said you would?*

---

## Four Item Types

Most task managers force everything into the same mold — title, due date, checkbox. But different commitments have fundamentally different behaviors. SoroSoro models each one properly.

**Deadline**
Time-bound goals with automatic urgency escalation: SOON (within 7 days) / URGENT (within 3) / TODAY / OVERDUE. Optional count-down progress auto-archives the item when it reaches zero.

**Recurring**
Things that need to keep happening — monthly reviews, checkups, weekly backups. Not a repeating reminder: each completion automatically calculates the next due date and logs a completion history.

**Tracker**
Managing finite resources: personal training sessions left, prepaid vouchers remaining, chapters to go in a book. Counts down to zero, then auto-archives. No manual cleanup needed.

**Todo**
A pressure-free bucket list: movies to watch, places to go, books to read. No deadline, no count. Just check it off when you get there.

## Three Visual Themes

The theme system goes beyond color swaps. Each theme has its own typography, spacing logic, and visual language — three distinct aesthetic identities.

**CYBER**
Late-night terminal aesthetic. `#060a10` deep background, cyan `#00d4ff` as primary accent, monospace fonts for data display, grid overlay and scanline animation, glowing shadows. Section headers styled as code comments: `// DEADLINES`.

**WABI**
Japanese minimalism. `#f4f0e8` warm cream background, DM Serif Display typography, zero border radius, hairline separators, generous whitespace. Restrained and quiet — nothing unnecessary.

**EDITORIAL**
American magazine style, inspired by TIME. A large red masthead displays the current date at the top. Playfair Display headlines, three heavy rules between sections, pinned items marked with a red star. The FAB is a square red button with a 3px black drop shadow.

## Features

- **Status system** — Deadline and Recurring items automatically reflect urgency based on days remaining, with distinct color highlights per state
- **Pin to top** — Surface important items within their section regardless of sort order
- **Count and progress** — Optional on Deadline / Recurring, required on Tracker; progress bar updates in real time
- **Archive history** — All item types land in a unified history view on completion, filterable by type, with completion date preserved
- **Custom tags** — 7 default categories with user-defined color overrides
- **Notifications** — Configurable lead time (1 / 3 / 5 / 7 days before deadline); Deadlines get a second notification on the due date itself; Recurring items notify on the due date
- **Bilingual** — Chinese and English, follows system locale by default, overridable in settings; date formatting is locale-aware

## Architecture

```
app/                        # Expo Router pages
  (tabs)/
    index.tsx               # Home — four typed sections
    history.tsx             # Archive with type filter
    settings.tsx            # Theme / language / notification settings
  add.tsx                   # Create / edit modal
  detail/[id].tsx           # Item detail and actions

components/                 # Presentational components, split by item type
  DeadlineCard.tsx
  RecurringCard.tsx
  TrackerCard.tsx
  TodoItem.tsx
  ProgressBar.tsx
  SectionHeader.tsx
  CyberGrid.tsx             # Grid background for CYBER theme

store/
  useStore.ts               # Zustand store — state and all business logic

lib/
  themes.ts                 # Three theme token objects (color / font / spacing)
  i18n.ts                   # Chinese and English strings
  dateUtils.ts              # Date math and status resolution
  notifications.ts          # Notification scheduling

types/
  index.ts                  # All TypeScript type definitions
```

**Fully local.** No backend, no accounts, no sync. All data lives on the user's device via AsyncStorage. Theme and language preferences persist alongside item data. Deliberately zero server dependency — faster, private by default.

## Design Decisions

**Type-driven data model** — The four item types are modeled as a TypeScript discriminated union. UI renders per-type, no generic compromises. Adding a new type means extending the union, not patching conditionals everywhere.

**Theme as a token system** — Themes are not applied via scattered if/else checks. Every component reads from a shared token object (`bg`, `accent`, `fontDisplay`, `radius`, etc.). Swapping themes is a single store update; adding a theme is adding one object.

**Zero backend by design** — Local-only architecture was a deliberate choice: no registration friction, no privacy surface area, no infrastructure to maintain. The app works fully offline from first launch.

**Minimal interaction paths** — The most common actions (Recurring "Done Today", Tracker +/-) are exposed directly on home screen cards. No modal, no navigation required.
